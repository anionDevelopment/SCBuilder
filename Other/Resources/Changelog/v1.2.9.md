# Release notes

## Changes
- Updated the versions of the used images
- Added the missing `MistralVibeVersion`-build-arg and its `Other/Resources/Dependencies/MistralVibe/Version.txt` (pinned to `2.24.3`), analogous to the other ai-cli-dependencies. The Dockerfile already installed `mistral-vibe` via `pip install mistral-vibe==${MistralVibeVersion}`, but the build-arg was never declared/supplied, so the version was empty.
- `opencode` is now installed via `npm install -g opencode-ai@${OpenCodeVersion}`, like the other ai-clis of this image, instead of the `curl https://opencode.ai/install | bash` install-script. Version.txt keeps the same pinned value (`1.18.15`), which is also a valid `opencode-ai`-release on npm.
- `Other/UpdateDependency.py`: `__update_dependency_opencode` now resolves the version from the npm-registry (`opencode-ai`) instead of the `sst/opencode` github-releases, matching the installation-mechanism above. Added the previously-missing `__update_dependency_mistralvibe` (resolves from PyPI, `mistral-vibe`), so `MistralVibe` is not silently skipped by future dependency-updates anymore.
- Installed `xvfb` (unpinned, like the other apt-packages of the "essential tools"-step) so a real, built flutter-linux-app can be launched headlessly in this container via `xvfb-run`, enabling full-app screenshots (e.g. `flutter test integration_test/...`) for visual-regression-testing of flutter-apps, in addition to the widget-tree-only golden tests `flutter test` already supported without any display.
