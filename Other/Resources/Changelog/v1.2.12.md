# Release notes

## Changes

- Fix.
- The nginx-example for `SCTaskRunnerAndroid` no longer rate-limits every build to death: it declared `rate=10r/m` with
  `burst=20`, while a client which waits for its job asks for the state and for the log of that job once per
  poll-interval (3 seconds by default), which is 40 requests per minute per running build. After about 30 seconds the
  burst was used up and every further request of a running build would have been answered with `429`.
- New specification `openspec/specs/task-runners/spec.md`: every `SCTaskRunner*`-codeunit has to return only the
  build-artifact of a job to its client and has to keep nothing of that build afterwards - neither the repository it
  received, nor the workspace, nor temporary files - and that must not depend on the client doing anything.
- The ReadMe of `SCTaskRunnerAndroid` states that the runner returns the folder the client stated its result is in (for
  an android-app-build the folder with the app-bundle) instead of the whole codeunit-folder. The implementation of that
  is in ScriptCollection; the runner-image needs the version which contains it.
- `RunningTheRunner.md` documents what the runner logs and where, and which error reaches the client: the complete
  output of a build which does not compile, but only an error-id and a `500` without details when the runner itself
  fails.
- The nginx-example for `SCTaskRunnerAndroid` is sized for the repositories which are actually transferred: the
  body-limit is `16g` instead of `4g` (a limit which is too small usually reaches the client as a reset connection
  instead of as a clean `413`), the proxy-timeouts are `1800s` instead of `900s`, and `send_timeout` is set, whose
  default of 60 seconds applies to the transfer of the result-archive back to the client. Why
  `proxy_request_buffering off` matters is documented instead of only being set.
