# Release notes

## Changes

- Updated dependencies.
- Added the kotlin-compiler (`kotlinc`, version `2.4.20`) to the `SCBuilder`-image, pinned via `Other/Resources/Dependencies/Kotlin/Version.txt` like every other dependency of that image. It is installed from the official release-artifact of `JetBrains/kotlin` and not from the debian-package `kotlin`, although that package exists: debian still ships kotlin `1.3.31` there, which is several major-versions behind the current compiler, and the debian-mirrors do not allow an exact version-pin anyway. The artifact is a jvm-application and therefore architecture-independent; it runs with the java which the image already contains. `UpdateDependency.py` raises the version from the tags of that repository, like it does for the other tools which are installed from a github-release
- Implemented the custom-script-hook of the entrypoint of the `SCBuilder`-image, which was a `TODO` before: if the environment-variable `CustomScriptPath` is set and not empty, the entrypoint runs the script it states before the actual command, so a container-start can be extended (a registry-login, a certificate, a mounted tool) without building an own image on top of this one. If the variable states a file which does not exist, or if the script fails, the container-start fails with an error instead of continuing, because the command would otherwise run in an environment which was not prepared without anybody noticing it; a failed script ends the container-start with its own exit-code, so the reason why it failed stays visible. The script is run by bash and not executed directly: the stated file is usually bind-mounted and a bind-mounted file does not necessarily carry the executable-bit, so executing it directly would let a file which exists fail with `Permission denied`
