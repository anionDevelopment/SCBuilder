# Release notes

## Changes

- Pinned flutter to the same version (`3.47.4`) in the `SCBuilder`-image and in the `SCTaskRunnerAndroid`-image and stopped updating it automatically. Both images build the same flutter-codeunit - the android-target on the runner, everything else in the builder-image - and a flutter-package states in its `pubspec.yaml` which Dart-SDK it is built with, so an environment whose flutter differs from the others either can not resolve the packages at all or produces screenshots which do not match the checked-in baseline-images of its visual-regression-tests. The automatic update raised the version of each image on its own, depending on where it ran last, which is exactly how the two drifted apart (`3.47.3` respectively `3.47.1`); the version is now raised by hand in both files together and on the machines of the developers
- Documented where the android-sdk-pins of the `SCTaskRunnerAndroid`-image come from, in its `Dockerfile` as well as in its `UpdateDependency.py`: the platform- and the ndk-version are the ones the Flutter-Gradle-plugin states in `packages/flutter_tools/gradle/src/main/kotlin/FlutterExtension.kt` (`compileSdkVersion` respectively `ndkVersion`) of the pinned flutter-version, so they are read from there when that version is bumped instead of being determined by running an android-build and watching which packages it downloads, which is what the comments demanded before. The build-tools-version is not stated by flutter at all - it follows the Android-Gradle-plugin of the built app. The pins themselves stay unchanged for the bump to `3.47.4`, because that release states the same values (`36` and `28.2.13676358`) as `3.47.1`
